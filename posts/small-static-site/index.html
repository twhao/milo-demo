一个小网站的构建清单：从 Markdown 到浏览器

个人网站不需要很复杂，但最好知道每一步发生了什么。我把写作、生成、预览与发布分开，从文章、模板到图片路径，整理出一份够用的构建清单。出了问题时，可以顺着它往回找，而不是急着全部重装。

写作与页面之间

刚接触静态博客时，我把 Markdown 文件理解成网页本身。后来才发现，文件更像原料：标题、时间、分类和正文先被读取，模板决定它们放在哪里，样式表再负责外观。

理解这条路径之后，排查问题就容易许多。标题写错，回到文章；所有文章都错位，检查模板或样式；本地正常而线上异常，再看路径、缓存和发布产物。不要一开始就删掉所有东西重新安装。

给步骤划出边界

  1. 在源文件里写作，确认日期和永久链接。
  2. 本地预览，检查正文而不只看首页。
  3. 生成静态文件，查看错误和资源路径。
  4. 确认产物之后，再单独决定是否发布。

图片路径最容易被忽略

相对当前页面寻找图片，和从网站根目录寻找图片，是两种不同的约定。文章一旦进入多级路径，原本正确的相对地址就可能失效。我给图片使用统一目录，并在文章页、第二页列表中各打开一次。

本地图片不会因为图床调整而留下空白，代价是需要控制尺寸。原图留在相册，网站只放适合屏幕阅读的版本；简单几何图形用 SVG，照片则控制分辨率和压缩质量。

一张够用的检查表

阶段 要确认的事
文章 标题、日期、摘要与正文相符
页面 导航可返回，目录指向对应章节
资源 图片正常加载，代码不撑破手机宽度
产物 不含草稿、临时文件与本机路径

这张表不会让网站永远不出错。它只是把一次模糊的“好像可以了”，变成几个能逐一回答的小问题。对一个下班后维护的个人博客来说，这已经节省了不少心力。
